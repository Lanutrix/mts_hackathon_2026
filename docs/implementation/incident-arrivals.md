# Поступления и первичные команды в учебном эфире

Каждые две минуты просмотра проигрывают один час поступлений. В начале сеанса модельные часы показывают понедельник, 09:00. Отдельный платёжный инцидент проходит пять сценарных шагов за 42 секунды. Новые карточки `SIM-FLOW-*` поступают в ту же временную JSON-выгрузку, проходят нормализацию и становятся доступны в API карточек, выгрузке и аналитике. Правила отбора в эфир применяются ко всем карточкам. Время `submitDate` соответствует моменту появления на часах стенда.

### Данные

Клаудио Амарал, Марсело Фантинато и Саражани Перес опубликовали обезличенный аудит ServiceNow одной ИТ-компании. В CSV 141 712 строк и 24 918 инцидентов. Мы оставили по одному открытию на `number`, взяли время `opened_at` и категорию, группу и приоритет из записи с минимальным `sys_mod_count`. При равенстве счётчика выбирали первую строку в файле. Часовой пояс исходного журнала неизвестен, поэтому модель использует записанные в нём местные сутки. Исходные данные доступны по лицензии CC BY 4.0. Репозиторий содержит агрегированные счётчики. ### Как генерируется нагрузка

1. На каждые модельные сутки выбираем с возвращением один учебный день того же типа. Берём из него все 24 почасовых количества, сохраняя утренние пики, разброс и связь между соседними часами. Будний день в обучении в среднем приносил 367,36 заявки, выходной — 45. Максимальная средняя интенсивность в рабочие дни отмечена с 09:00 до 10:00 и составила 46,43 заявки/ч.
2. Размещаем нужное число поступлений в случайные равномерные моменты внутри каждого часа. Для каждого выбираем категорию по частотам соответствующего часа и типа дня. Чтобы в редких часах сохранить разнообразие, к выборке добавляем общую смесь категорий с весом 24 наблюдения.
3. Выбираем первичную группу по категории, сглаживая её частоты общей смесью групп с весом 12 наблюдений. Общее распределение групп получает по 0,5 наблюдения на каждый исход, включая неизвестную ранее группу. Приоритет выбираем по общему распределению обучения. Время ремонта, производительность персонала и переходы между командами по этому журналу не оценивались.
4. Используем обезличенный номер группы и категории. Например, «Учебная группа 70» соответствует `Group 70`, а «Учебный сервис 42» — `Category 42`. Значение `?` при назначении оставляет группу пустой. Названия симптомов синтетические. Для оценки нагрузки подразделений МТС потребуются их собственные назначения и временные метки.

Для интенсивности проверяли математическое ожидание генератора, для группы — распределение вероятностей. Базовый прогноз по предыдущей неделе использует только данные, известные к каждому оцениваемому часу. Интервал между 10-м и 90-м процентилями учебных почасовых количеств покрыл 82,66% контрольных часов, включая равенство границе. В обучении встретилось 67 известных групп. Первичная группа пропущена у 845 учебных и 59 контрольных обращений. В мае один инцидент пришёл в ранее не встречавшуюся группу. В проверке пропуск и новый идентификатор считаются разными исходами.

За май модель ожидала 8 487 обращений при 7 508 наблюдавшихся, завышение на 13,0%. С июня журнал меняется: в 6 240 полных часах до 16 февраля 2017 видны лишь 272 открытия. Почасовая ошибка календарного прогноза достигает 11,44 против 11,52 у постоянного среднего. Причина редких записей неизвестна. Выводы по маю относятся к периоду плотного наблюдения. Отдельной проверки внутриминутных всплесков, праздников, переноса на другие компании и правильности назначения с точки зрения инженеров здесь нет. ### Воспроизведение и наблюдение

Из корня репозитория, Python 3.10+ и Node.js 24:

```sh
python scripts/fit_incident_arrivals.py
node --import tsx --test --test-concurrency=1 tests/incident-arrivals.test.ts tests/jury-simulation.test.ts
```

Скрипт загружает официальный архив и пересоздаёт профиль `apps/server/arrivalProfile.json` вместе с отчётом. Для локальной копии архива доступен параметр `--archive PATH`. На сервере профиль читается локально. В активном сеансе `/api/dashboard?ns=simulation` возвращает `simulation.arrivals` с модельным временем, ускорением, средней часовой интенсивностью, числом поступлений и ID последней карточки. Экспорт содержит последние 96 модельных карточек и временно удерживает карточки из журнала последних 24 сигналов. Пауза сервера останавливает модельные часы.
