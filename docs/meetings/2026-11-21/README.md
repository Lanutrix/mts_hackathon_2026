## Что дежурному нужно увидеть

В разговоре приводят ориентир в 800–900 инцидентов в разных состояниях. Дежурный вручную отбирает небольшой список, проверяет приближающиеся сроки и связывается с нужными людьми. Дашборд должен собрать эту выборку и показать причину включения каждой записи. Численность приведена со слов участника и описывает рабочий контекст встречи. ## Где проходит граница MVP

При передаче записи в группу команда сама определяет исполнителя. В разговоре различают назначение, начало работы, завершение и закрытие. Для реализации точные коды состояний и состав четырёх выборок закреплены в проектной спецификации. [156 · 12:00–13:59](transcripts/recording-156.md#m12)

Запись уже существует в ITSM. В разговоре систему называют SimpleOne. Дашборд читает состояние и делает заметными нужные дежурному случаи. Учёт изменений и работа команды над устранением остаются в ITSM. На встрече допустили дополнительную команду переназначения из интерфейса и имитацию ответа ITSM для демо. Конкретный контракт API на встрече не зафиксирован. [156 · 17:00–18:59](transcripts/recording-156.md#m17) · [156 · 20:00–23:59](transcripts/recording-156.md#m20)
