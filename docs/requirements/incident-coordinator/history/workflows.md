# Сквозные сценарии: User Flow

**Статус:** предварительный проект; пути описаны по итогам дискуссии, а не подтверждены владельцем процесса.

## Базовый маршрут

1. Инициатор сообщает проблему (ручной ввод / бот / технический алерт).
2. IN создаёт нормализованную запись, фиксирует источник и первичные данные.
3. ANL предлагает тип, приоритет, SLA, целевую команду и объяснение выбора.
4. При допустимой уверенности и правилах — автопередача; иначе ручное подтверждение координатора.
5. OUT передаёт инцидент исполнителю; исполнитель отдельно подтверждает получение.
6. Система показывает ход исполнения, риски и дедлайны; отправляет уведомления по правилам.
7. Исполнитель предлагает решение. Система запрашивает подтверждение у инициатора или валидного проверяющего канала.
8. После подтверждения инцидент закрывается и добавляется в историю. Если подтверждения нет — возвращается в работу.

## Исключения для обязательного прототипирования

| Сценарий | Ожидаемая реакция | Что выяснить |
|---|---|---|
| Ошибочная команда | Отклонение, переназначение, журнал причины | Кто вправе менять исполнителя, как считается SLA |
| Низкая уверенность модели | Сигнал координатору и объяснение альтернатив | Пороги уверенности, правила эскалации |
| Приоритет вырос после ожидания | Пересчёт/эскалация согласно регламенту, без потери истории | Считать от первого сигнала или от смены приоритета |
| Команда не отвечает | Таймер подтверждения, напоминания и эскалация | Частота и получатели уведомлений |
| Подтверждение отсутствует | Ожидание, повторная проверка или ручной разбор | Признаки верификации по каналам |
| Инициатор отклонил «решено» | Reopen с историей прошлого решения | Правила возврата и ответственность |
| Несколько команд | Группа исполнителей + явный владелец инцидента | Primary owner / очередность / параллельность |
| Несколько схожих обращений | Кандидат на агрегацию, сохранение внешних ссылок | Дедупликация и связь массового сбоя |
| Недоступность интеграции | Повторные попытки, очередь, видимость ошибки | Политика ретраев и идемпотентности |

## Демонстрационный User Flow

Гость пишет текст/голос в бота → UI отображает новый тикет → ANL объясняет выбор → команда-симулятор подтверждает/отклоняет → при отклонении система переназначает → исполнитель сообщает результат → бот-инициатор подтверждает или отклоняет → статус/таймер/аудит обновляется.

Разбор и приоритеты разработки — в [задании Work](../../research/incident-coordinator/work-brief.md).
