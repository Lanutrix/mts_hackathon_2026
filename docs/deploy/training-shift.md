# Обновление учебной смены

Чистый демоисточник содержит 800 заявок. Идентификаторы первых 600 совпадают с предыдущей учебной сменой. В исходном наборе работают 26 профильных команд и координаторы. Справочник исполнителей строится из текущих записей. После миграции в нём также остаются прежние группы и люди.

Команда обновления предназначена для старого набора из 600 строк генератора с seed 42. Она распознаёт обе версии кодов типов услуг. Сервер создаёт новый набор при первом запуске с отсутствующим демофайлом. Обновление существующей установки выполняется явно.

## Проверка перед записью

1. Остановите сервис и другие процессы, которые могут записывать этот файл. Сделайте согласованную [резервную копию источника и БД](backup-restore.md).
2. Получите ID заявок с решениями по маршрутизации из базы данных. Убедитесь по таблице `incidents`, что номера DEMO-42-00601…00800 и их ключи sysId ещё не заняты в истории демоисточника. При остановленном приложении внешний PostgreSQL остаётся доступен.
3. Запустите предварительную проверку. Укажите все полученные ID повторяющимися параметрами `--preserve-id`. Для новых 200 записей зафиксируйте момент смены в `--clock`. Существующие даты остаются привязаны к источнику.

```sql
SELECT DISTINCT i.id
FROM dispatch_decisions d
JOIN incidents i USING (namespace, key)
WHERE d.namespace = 'demo'
ORDER BY i.id;
```

```bash
node --import tsx scripts/upgrade-training.ts "$demo_file" --clock "$shift_clock" "${protected_args[@]}"
```

Здесь `demo_file` — путь к исходному файлу демо, `shift_clock` — время в ISO 8601 с часовым поясом. Bash-массив `protected_args` содержит отдельные пары флаг/значение для каждого ID (например, `protected_args=(--preserve-id DEMO-42-00018)`). Если журнал пуст, задайте `protected_args=()`.

## Запись и сверка

Предварительный режим печатает SHA-256 текущего файла, число записей до и после, число полностью сохранённых строк и количество групп. При совпадении абсолютного пути и контрольной суммы выполните ту же команду с параметром `--apply`.

```bash
node --import tsx scripts/upgrade-training.ts "$demo_file" --clock "$shift_clock" "${protected_args[@]}" --apply "$verified_sha256"
```

Мигратор целиком сохраняет строки с пользовательскими изменениями, дополнительные записи и заявки из списка защищённых ID. Для неизменённых строк он сохраняет идентичность, статусы, приоритеты, сроки, время и признаки. Учебные описания и примеры решения обновляются. Предыдущее назначение у координаторов сохраняется. От каждого сочетания старой команды и исполнителя в файле остаётся представитель. Добавляются номера 00601–00800. При недостающих исходных ID, смене ключа или конфликте с новым ID команда завершится до записи. Повторный запуск распознаёт обновлённую смену.

Запустите сервис и проверьте ревизию, счётчики, состав команд и журнал решений по защищённым заявкам. Штатный приём снимка добавляет историю изменений, сохраняя предыдущие события и решения. Новые заявки могут вызвать обычные сигналы об инцидентах. Рабочий источник `workspace` имеет собственный жизненный цикл. Кнопка «Сброс» в демо создаёт новую историю демонстрации.
