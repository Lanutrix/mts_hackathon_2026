# Срез — рабочее место координатора

Демонстрационный стенд наблюдения за инцидентами из JSON-выгрузки. Координатор видит четыре независимые группы, историю и уведомления, может открыть кейс или собрать аналитический холст вопросом на русском языке. Разбор через VseLLM показывает основания в полях ITSM и следующую ручную проверку.

## Аналитика и приём инцидентов

[Как работают очередь, группировки, советы и аналитический холст](docs/implementation/algorithms.md)

В помощнике запрос «Общее число инцидентов» открывает число записей и распределение по статусам. «Анализ времени по командам» показывает медиану от регистрации до фактического решения и число заявок для каждой команды из снимка. Команду или симптом можно открыть до исходных карточек. Открытые заявки и записи без корректной пары дат исключаются из расчёта времени. «Значки в системе» открывают иллюстрированный словарь.

В эфире «Группы инцидентов» обновляются вместе с очередью. Координатор выбирает группу и видит её заявки в реестре. Кнопка «Подробнее» открывает разбор с исходными карточками. VseLLM подбирает группы, подписи и значки по обезличенным признакам описаний и диапазонам нагрузки. Пока готовится ответ или модель недоступна, эфир показывает локальную группировку. В фильтрах можно ограничить очередь по симптому, продукту, приоритету, команде и порядку разбора.

Администратор открывает «Приём инцидентов» из меню профиля. На [странице рабочей копии](https://mts-watermelon.ru/intake?ns=workspace) можно заполнить одну заявку или вставить JSON-объект либо массив. Повтор идентичной записи подтверждается отдельно. При конфликте идентификатора вся отправка отклоняется. Исходная выгрузка доступна для чтения.

## Локальный запуск

Node **24.18.0**, npm **11.16.0**. Установка зависимостей строго по package-lock.json:

```sh
npm ci --ignore-scripts
npm run build
npm run dev
```

Откройте http://127.0.0.1:3000. При первом запуске сервер создаёт в `.runtime/demo/incidents.json` учебную смену из 800 заявок. В ней 26 профильных команд и группа координаторов. У каждого из 104 видов сбоя есть наблюдение, диагностическая проверка и способ восстановления. Состояния, исполнители, города и измерения различаются. PostgreSQL-совместимый PGlite хранит проекцию в `.runtime/db`. Измените файл отдельным процессом — интерфейс обновится без перезагрузки. Не запускайте два backend над одним DATA_DIR.

Существующую учебную смену можно [обновить с сохранением истории и назначений](docs/deploy/training-shift.md).

```sh
npm run generate -- 120 42 .runtime/acceptance
npx tsx scripts/mutate.ts .runtime/demo/incidents.json critical
```

Создание пользователя — в собственном интерактивном терминале, пароль не отображается и не передаётся аргументом:

```sh
npm run user -- operator demo-admin .runtime/users.json
```

Затем задайте `USERS_FILE` на созданный файл и перезапустите сервер. В PowerShell: `$env:USERS_FILE='.runtime/users.json'`; в POSIX shell: `export USERS_FILE=.runtime/users.json`. Фиксированного admin-пароля нет. Viewer читает, coordinator анализирует и сохраняет личные отметки, demo-admin управляет рабочими копиями и сценарием.

Для оригинального файла задайте `ORIGINAL_PATH` на внешний защищённый путь. Оригинал доступен только авторизованным и только для чтения; в Git и публичной демонстрации его нет. Импорт оригинального формата выполняйте в приватную рабочую копию. `DATABASE_URL` переключает хранилище на PostgreSQL; на VDS предусмотрена peer-аутентификация через Unix socket.

`.env.example` описывает настройки; автоматической загрузки .env нет — передавайте переменные средой или systemd EnvironmentFile. `ITSM_URL` принимается только как HTTPS URL без credentials. Без него показан явно обозначенный макет с тем же ID.

## Установка приложения и уведомления

«Срез» устанавливается из меню браузера или кнопкой «Установить приложение» в личных настройках, когда браузер предлагает установку. На iPhone и iPad с iOS/iPadOS 16.4 и новее добавьте сайт на экран «Домой» и откройте его с иконки. Откройте сайт по HTTPS, войдите в аккаунт и в настройках выберите источник, затем нажмите «Включить уведомления». «Проверить уведомление» отправляет одно сообщение на текущее устройство. [Web Push на iOS и iPadOS](https://webkit.org/blog/13878/web-push-for-web-apps-on-ios-and-ipados/)

После принятия снимка сервер сообщает о новых критических инцидентах, повторном открытии критического инцидента, назначении координаторам и решении критического инцидента. Устройство получает до одного сообщения в минуту. Одиночное событие открывает карточку, серия событий — журнал выбранного источника. На заблокированном экране видна общая фраза об обновлении. Выход из аккаунта отзывает подписку текущего браузера. Остальные устройства управляются отдельно.

Пара ключей VAPID создаётся при первом обращении и хранится в `DATA_DIR/secrets/web-push.json` с правами 0600. Включите этот файл в закрытую резервную копию вместе с базой подписок. Для контакта с операторами push-сервисов можно задать `VAPID_SUBJECT` (HTTPS-адрес или mailto). Сервер отправляет шифрованные сообщения через службы Google, Mozilla, Apple и Microsoft по HTTPS. Учебная симуляция не создаёт системные уведомления. Данные карточек загружаются после входа по сети. [Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)

## Проверки и синтетика

```sh
npm test
npx playwright install chromium firefox webkit
npm run test:e2e
npm run ai:smoke
npx tsx scripts/fixtures.ts
npx tsx scripts/benchmark.ts
npx tsx scripts/soak.ts
```

`npm test` без ORIGINAL_PATH пропускает единственную проверку закрытого оригинала. Локальный отчёт включает её фактический запуск. AI smoke загружает публичную закреплённую ONNX-модель один раз; после кэширования работает локально. Этот запрос действительно выполняет ML; CI использует отдельный ограниченный mock для ошибок/таймаутов. Без модели показывается подписанный fallback.

### Серверный разбор через VseLLM

Поместите ключ в `DATA_DIR/secrets/vsellm.key` с доступом только для сервисного пользователя и перезапустите приложение. `VSELLM_API_KEY_FILE` задаёт другой путь. Если окружение содержит `VSELLM_API_KEY`, сервер использует его. По умолчанию используется `openai/gpt-4.1-mini`, имя модели задаёт `VSELLM_MODEL`.

На вопрос «Что такое инцидент?» помощник сразу показывает определение, пример и ссылку на соответствующий раздел справки. Примеры и инструкции опираются на один [словарь платформы](packages/domain/assistantGuide.ts). Для вопросов по заявкам VseLLM предлагает ограниченный план, а сервер проверяет его и считает показатели по доступной пользователю выборке. При недоступности модели поддержанные запросы разбираются локально.

В учебных источниках `demo` и `simulation` помощник отвечает на свободные вопросы, может переформулировать свой ответ и вернуться к аналитике. Для диалога сервер хранит до трёх последних разговорных реплик в памяти на 15 минут. Контекст привязан к пользователю, источнику и учебному запуску. Во время генерации видны прежний срез, время ожидания и кнопка остановки.

Пользователь может запросить один из [81 показателя](packages/contracts/answerInsights.ts), один из [26 дополнительных блоков анализа](packages/contracts/answerCatalog.ts) или сочетание нескольких блоков. «Возраст очереди» строит распределение заявок по времени, «Связи продуктов и команд» показывает частоты пар с переходом к исходной заявке, «Покажи доли команд круговой диаграммой» строит диаграмму с детализацией по сектору. Стартовый холст показывает текущую выборку без обращения к модели.

API разбора подборки также принимает вопросы по 1–6 заявкам от координатора и demo-admin. Быстрые вопросы о сроках и ответственных возвращают поля ITSM сразу. Вопросы о причинах, симптомах, риске и следующем действии обрабатывает модель. Разбор кейса доступен также авторизованным зрителям демо и учебного эфира. Результат содержит имя модели, фактические ID и поля для сверки. Ответ ограничен переданными признаками. Решение о действии принимает координатор.

В эфире блок «Следующий шаг» показывает одну ручную проверку, её основание и ссылку на карточку. Данные берутся из текущей выборки. Новые события и переход срока в другую категорию обновляют совет. Источник сразу даёт проверяемую рекомендацию, а VseLLM может уточнить формулировку. При смене группы ответы к прежнему срезу отбрасываются.

На рабочих источниках `workspace` и `original` помощник передаёт модели операционные слова и условные обозначения выбранных записей. В учебном диалоге используется очищенная формулировка пользователя. Сервер скрывает контакты, типовые секреты и сопоставленные фрагменты записей. Для анализа конкретных заявок действуют отдельные правила передачи полей. В `simulation` разрешены фрагменты встроенных синтетических описаний.

Один веб-процесс допускает до трёх параллельных вызовов, 18 за минуту и 500 за скользящие сутки. Фоновое уточнение рекомендаций занимает не более одного одновременного вызова, шести за минуту и 180 за сутки. Это оставляет ресурс для вопросов координатора. Одинаковые запросы объединяются, успешный результат хранится в памяти пять минут. При ошибке провайдера, исчерпании лимита или неподтверждённых ссылках экран показывает поля источника и причину перехода. Без ключа для обычного разбора кейса доступны локальные TextRank и E5 при установленных весах.

Генератор: seeds 42/43/44/92831, 120/600/2000/10000 записей; фиксированные часы, независимый oracle и manifests. `--live` сдвигает время только новой копии. `data/demo/design.json` — одинаковая синтетика для Figma и визуальной проверки. Пограничные случаи — `data/demo/boundaries.json`.

## Навигация по реализации

- `packages/domain`: исходная схема, нормализация, группы, transitions, генератор.
- `apps/worker`: стабильное чтение файла, transactional ingestion и восстановление.
- `apps/server`: API, роли, история/read state, audit, AI worker и staging support.
- `apps/web`: React, Golos Text, semantic CSS tokens, доступные формы и wallboard.
- `packages/contracts/openapi.json`: фактические маршруты и DTO.
- `docs`: требования, ADR, дизайн, доказательства, runbooks и сценарий защиты.

F37–F40 (канальные адаптеры, routing/ACK/телефония) отложены явно. Статус публичного домена и VDS проверяется отдельно от успешной локальной сборки.
